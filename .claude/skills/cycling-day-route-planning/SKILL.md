# Skill：單車環島每日路線規劃文件產生

## 📌 目的

根據 `index.md` 的 10 天環島總覽，為每一天**循序漸進地**產生四份檔案，確保行程既符合大方向，又具備單車實戰的合理性與精確度：
1. **`dayN_mymap.csv`**：Google My Maps 匯入用的精確點位 CSV 檔案
2. **`dayN_route.gpx`**：透過路線引擎產生的實際 GPS 路線軌跡檔
3. **`dayN_prompt.md`**：每日行程海報的圖像生成提示詞
4. **`dayN.md`**：彙整上述資訊的詳細路線行程 Markdown 文件

---

## 📁 目錄結構

每天的檔案放在各自的 `dayN/` 資料夾中：

```
CyclingTW/
├── index.md                    ← 10 天環島總覽
├── prompt.md                   ← 海報提示詞主體骨架
├── 主角.png                    ← 圖像參考
├── day1/
│   ├── day1_mymap.csv          ← (產出 1) 地圖點位資料
│   ├── day1_route.gpx          ← (產出 2) GPS 軌跡路線檔
│   ├── day1_prompt.md          ← (產出 3) 海報提示詞
│   └── day1.md                 ← (產出 4) 彙整行程文件
└── ...
```

## 🔄 標準作業流程 (SOP) 與 Checklist

請務必**嚴格依照以下順序**執行規劃，前一步驟的產出為後一步驟的基礎：

### Phase 1: 規劃停靠點 (產出 CSV)
- [ ] **讀取快取**：先檢查 `dayN/map/index.json` 是否存在。若存在，直接載入已快取的地點資料（含 `bayesian_score`、`visual_score`），跳過對應的 API 呼叫；僅對快取中缺少或需更新的地點補充查詢。
- [ ] **確立核心路線**：從 `index.md` 取得該日的出發地、目的地、指定走向與必經景點。使用 `mcp_google-maps_maps_directions` 以 `bicycling` 模式計算大略路線與距離。
- [ ] **動態擴充點位**：嚴格調用 `mcp_google-maps_maps_search_places` 工具，沿著必經之路尋找合適的停靠點。⚠️ **節省 API 額度規定**：尋找「便利商店」、「加油站」、「公共設施」等不參與排名的點位時，僅使用搜尋結果即可，**嚴禁**對其調用 `mcp_google-maps_maps_place_details`。
  - **單車視角選點原則**：
    - **需求導向**：必須涵蓋單車騎乘所需的補給（便利商店/飲水）、休息、景點觀光、午餐（餐廳大休）。
    - **合理與順路**：停靠點必須貼近原路線，避免為了景點或補給造成不合理繞路；一般補給/公廁距主線建議不超過 500m，午餐大休不超過 1km，景點不超過 2km。若 `index.md` 指定的四極點或必經景點超過上述距離，可納入但必須在備註說明中明確標示繞行距離與原因。時間安排也要恰當（例如出發後 20-30km 安排休息，中午時段安排有冷氣的午餐點）。
    - **貝葉斯輔助挑選**：先挑出足夠多且符合順路/時間合理的候選點；其中 `景點`、`起終點`、`餐廳大休` 都要查評分與評論總數，並計算 `bayesian_score`。候選景點/餐廳很多時，優先選 `bayesian_score` 較高者加入 `dayN_mymap.csv`，再依實際補給需求與路線節奏做最後取捨。
- [ ] **產出 CSV**：將結果寫入 `dayN/dayN_mymap.csv`，格式詳見下方規範（必須明確標示起點與終點）。
- [ ] **寫入快取**：將本次查詢過的所有地點（含入選與未入選候選）依格式存入 `dayN/map/`，詳見下方「Google Maps 資料快取機制」。

### Phase 2: 產生實體軌跡 (產出 GPX)
- [ ] **讀取座標**：將 CSV 中的「地點搜尋關鍵字」轉換為精確經緯度（捨棄海面上或無路之地的無效座標，確保可導航）。
- [ ] **產出 GPX**：透過 `openroute-mcp` 工具（或撰寫 Python 呼叫 OpenRouteService API），設定模式為自行車 (`cycling-regular`)，依序串接座標，並將軌跡結果存檔為 `dayN/dayN_route.gpx`。

### Phase 3: 生成圖像提示詞 (產出 Prompt)
- [ ] **參照骨架**：讀取共用模板 `prompt.md` 與參考圖 `主角.png`。
- [ ] **擷取亮點**：從剛產生的 `dayN_mymap.csv` 中，依照下方「Visual Score 視覺知名度排序規則」挑選主視覺景點。對所有 `景點` 與 `起終點` 計算 `visual_score = bayesian_score × log₁₀(評論總數)`，取最高者且具明確視覺符號的點作為海報主角。
- [ ] **產出提示詞**：置換模板變數，產生 `dayN/dayN_prompt.md`。

### Phase 4: 彙整總結報告 (產出 Markdown)
- [ ] **彙整資訊**：將上述決定的 CSV 點位、GPX 路線、配速建議進行總整理。
- [ ] **繪製圖表**：使用 `ishikawa-beta` 語法繪製詳細魚骨圖解。
- [ ] **產出文件**：撰寫並儲存為 `dayN/dayN.md`，結構詳見下方規範。

## 📋 dayN_mymap.csv 檔案格式

### CSV 欄位定義

為求精確分析與後續處理，採用以下欄位結構：

```csv
景點名稱,地點搜尋關鍵字,順序,類型,評分,評論總數,bayesian_C,bayesian_m,bayesian_score,備註說明
```

| 欄位 | 說明 | 範例 |
|:---|:---|:---|
| 景點名稱 | 顯示在地圖上的標記名稱 | `蘆洲柳堤公園` |
| 地點搜尋關鍵字 | Google Maps 搜尋用的精確關鍵字 | `新北市蘆洲區柳堤公園` |
| 順序 | 沿途順序編號（從 1 開始） | `1` |
| 類型 | 分類標籤（見下方類型表） | `起終點` |
| 評分 | Google Maps 星等（1.0-5.0） | `4.5` |
| 評論總數 | Google Maps 評論總數（直接填入 API 回傳數字 `total_ratings`，即 Google Places API 的 `user_ratings_total`） | `1250` |
| bayesian_C | 當日參與評分點位的平均評分 | `4.3` |
| bayesian_m | 當日參與評分點位的評論數中位數（最低採 100） | `800` |
| bayesian_score | 依貝葉斯公式計算出的加權分數 | `4.37` |
| 備註說明 | 補充資訊（預計抵達時間、設施、推薦原因） | `早上 07:00 出發，河濱出發點` |

> ⚠️ **精確度要求與 API 節流**：調查「景點」、「起終點」、「餐廳大休」時，務必呼叫 `mcp_google-maps_maps_place_details` 取得 `total_ratings`（cablate MCP 對應 Google Places API 的 `user_ratings_total`）並填入 CSV，這是衡量熱門度的最客觀數據。尋找「便利商店」、「加油站」、「公共設施」等補給類型時，**嚴禁**呼叫 place_details，相關欄位直接留空。

### 類型分類

| 類型值 | 說明 | 需填評分與評論數 |
|:---|:---|:---:|
| `起終點` | 當日出發點或終點 | ✅ |
| `景點` | 觀光景點、拍照打卡點 | ✅ |
| `便利商店` | 7-11、全家、萊爾富等 | ❌ |
| `加油站` | 中油等，可借廁所 | ❌ |
| `餐廳大休` | 午餐或長時間休息的用餐地點 | ✅ |
| `綜合休息站` | 有多種設施的複合休息站 | ❌ |
| `公共設施` | 公廁、飲水機等公共設施 | ❌ |

### 地點搜尋關鍵字撰寫原則

1. **便利商店**：使用「品牌 + 門市名稱」，例如 `7-ELEVEN 觀湖門市`
2. **加油站**：使用「台灣中油 + 站名」，例如 `台灣中油大園站`
3. **景點/漁港**：使用「縣市 + 景點名」，例如 `桃園永安漁港`
4. **公共設施**：使用完整地址或附近知名地標搜尋
5. **避免模糊關鍵字**：不要只寫「加油站」或「7-11」，要加上具體門市/站名

### CSV 範例

```csv
景點名稱,地點搜尋關鍵字,順序,類型,評分,評論總數,bayesian_C,bayesian_m,bayesian_score,備註說明
蘆洲柳堤公園,新北市蘆洲區柳堤公園,1,起終點,4.3,1250,4.3,800,4.31,早上 07:00 出發 河濱出發點
八里左岸,新北市八里左岸自行車道,2,景點,4.4,800,4.3,800,4.35,推薦景點
7-11 八里門市,7-ELEVEN 八里門市,3,便利商店,,,,,,離開八里前補充水分
林口水牛坑,林口水牛坑,4,景點,4.2,250,4.3,800,4.28,值得一看
永安漁港 / 海螺館,桃園永安漁港,5,餐廳大休,4.3,600,4.3,800,4.30,中午12:00 午餐大休 有冷氣與公廁
```

- 插入 `ishikawa-beta` 魚骨圖來視覺化當日行程。
- **作圖規範與 Emoji**：請直接且嚴格遵循 `mermaid-ishikawa-fishbone.md` 技能中的所有規範（包含為了時間軸的**倒序排列**、上下主骨交替規則，以及**專屬 Emoji 對照表**）。
- **本文件專屬設定**：魚頭（目標）的文字必須固定為 `Day N 完騎 目的地 距離`。

- 將全程分成 3~5 段

## 🎨 產生海報提示詞規則 (`dayN_prompt.md`)

`dayN_prompt.md` 的內容是以 `prompt.md` 作為主體骨架，每日需置換以下 **5 個變數**：

---

#### 置換變數 1：行程主題標題（新增於提示詞最前方）

在提示詞的最前方，必須加上該日行程的主題與基本資訊，以利於辨識：

- **格式範例**：
  ```text
  Day1 
  新北蘆洲 -> 苗栗竹南
  約 95 - 110 公里
  西濱海岸線追風之旅
  ```
- **說明**：包含天數、起迄點、距離，以及一個根據該日路線特色發想的「副標題主題」（例如：西濱海岸線追風之旅）。

---

#### 置換變數 2：主景點（構圖三大焦點）

依據 `dayN_mymap.csv` 計算 **Visual Score**，決定畫面三大焦點：

- **候選範圍**：主視覺只從 `景點`、`起終點` 兩種類型中挑選；`餐廳大休`、`便利商店`、`加油站`、`綜合休息站`、`公共設施` 不參與主視覺排序。`景點`、`起終點`、`餐廳大休` 都必須填入評分與 `評論總數`，但 `餐廳大休` 只供行程與午餐情境參考，不得納入主視覺排序。

- **兩階段評分系統**：
  - **Bayesian Score（品質排名，用於 CSV 停靠點挑選）**：修正評論數差距，讓少量評論的高分點與大量評論的普通點能公平比較。
    - `R` = 該點 Google Maps 評分
    - `v` = 該點 評論總數
    - `C` = 當日所有候選點（景點/起終點/餐廳大休）的平均評分
    - `m` = 當日候選點評論數的中位數；若中位數低於 100，採用 100 作為最低先驗強度（以適應東部或偏鄉路線）
    - `bayesian_score = (v / (v + m)) * R + (m / (v + m)) * C`
  - **Visual Score（知名度 × 品質，用於海報主視覺選點）**：海報主視覺需要觀眾認得出來，因此在品質之上再乘以對數人氣，讓高評論數的知名地標取得應有的優先權。
    - `visual_score = bayesian_score × log₁₀(評論總數)`
    - ⚠️ 純以 `bayesian_score` 選主視覺會懲罰高評論數的知名大景點（評分被拉向均值），違反「知名度高 = 觀眾更有共鳴」的常理，故必須改用 `visual_score`。

- **主角位置（畫面最大）**：對所有 `景點`、`起終點` 計算 `visual_score`，優先選最高者且具備明確視覺符號的候選點 → 置換 `prompt.md` 中的「地點」、「場景元素」、「動作」、「表情」。並在 CSV 備註欄記錄 `★主視覺 visual_score:XX.XX`。
  - 視覺符號包含：燈塔、廟宇、老街、漁港、濕地、山景、海岸、車站建築、橋梁、特殊地貌等。
  - `餐廳大休` 不作為主角位置參考；若餐廳本身位於具代表性的地標型空間（例如漁港、老街市場、特色建築、觀光休息站），應改以該地標建立 `景點` 點位後再納入主視覺排序。
  - 若最高 visual_score 候選點視覺辨識度不足，改選排序中下一個具代表性的候選點。
- **小分身位置（起點）**：置換 `prompt.md` 中的「小分身位置」為當日出發地，呈現「準備出發」情境。
- **沿途人氣景點（終點與其他）**：置換 `prompt.md` 中的「整體構圖」，將終點放遠景，沿途次要景點以精緻小模型點綴。

**景點文字規範**：
- **所有重要地理位置（景點、城市、路線、海灣等）必須使用中文字呈現**，例如：「大甲鎮瀾宮」、「白沙屯拱天宮」、「竹南車站」、「鹿港老街」
- 禁止使用 emoji 標記熱門地標，改用「人氣景點」等純文字描述

---

#### 置換變數 3：解析度

依據 `dayN.md` 起終點判斷路線走向，在提示詞最開頭加入：

- **南北走向**（如西濱）：`Output format: vertical portrait poster, aspect ratio 2:3.`
- **東西走向**（如橫貫）：`Output format: horizontal landscape poster, aspect ratio 3:2.`

---

#### 置換變數 4：光線氛圍

置換 `prompt.md` 中的「畫面質感」光線描述：

- **預設**：`柔和清晨明亮光線、清新藍天白雲`
- **若行程包含夕陽景點**（如高美濕地）：改為 `金色夕陽暖光、橘紅天空漸層、黃昏氛圍`

---

#### 置換變數 5：地理正確性說明

將 `prompt.md` 中台灣地圖的起終點說明，置換為當日實際路線：
- **起點在畫面上方，終點在畫面下方**（不一定是北南，依當日實際騎行方向決定）
  - 例如：西濱路線 Day 1-2 是由北往南，起點（台北/竹南）在上，終點（竹南/鹿港）在下
  - 例如：花東縱谷 Day 7 是由南往北，起點（太麻里）在下，終點（玉里）在上

> ⚠️ **起點與終點絕對不能錯置**：
> - 起點必須是**當日 `dayN_mymap.csv` 中順序第 1 筆**的地點
> - 終點必須是**當日 `dayN_mymap.csv` 中順序最後 1 筆**的地點
> - 不可把昨天或明天的地點誤植為起終點，每天獨立確認
- 沿途景點的相對位置描述（海在哪側、山在哪側、景點在哪段）

## 🗄️ Google Maps 資料快取機制

每天規劃完成後，必須將當次查詢過的所有地點資料存入 `dayN/map/` 目錄，以 `place_id` 為檔名，避免短期內重複呼叫 API。

### 目錄結構

```
dayN/
└── map/
    ├── index.json                 ← 總索引（入選 + 未入選候選）
    ├── {place_id}.json            ← 各地點完整資料
    └── ...
```

### index.json 格式

```json
{
  "day": N,
  "route": "起點 → 終點",
  "fetched_at": "YYYY-MM-DD",
  "bayesian_C": 4.29,
  "bayesian_m": 1423,
  "places": [
    {
      "place_id": "...",
      "name_zh": "...",
      "csv_type": "景點 / 起終點 / 便利商店 / 餐廳大休",
      "rating": 4.2,
      "total_ratings": 41574,
      "bayesian_score": 4.20,
      "visual_score": 19.40,
      "location": { "lat": 25.117, "lng": 121.244 },
      "source": "place_details 或 search_result",
      "note": "★主視覺 / ★午餐首選 等標記"
    }
  ],
  "candidates_not_selected": [
    {
      "place_id": "...",
      "name_zh": "...",
      "rating": 4.2,
      "total_ratings": 35328,
      "visual_score_estimate": 19.10,
      "source": "search_result",
      "not_selected_reason": "未入選原因說明"
    }
  ]
}
```

### 各地點 {place_id}.json 格式

```json
{
  "place_id": "...",
  "name": "英文名或中文名",
  "address": "完整地址",
  "location": { "lat": 25.117, "lng": 121.244 },
  "primary_type": "tourist_attraction",
  "rating": 4.2,
  "total_ratings": 41574,
  "opening_hours": { "weekday_text": [...] },
  "phone": "...",
  "website": "...",
  "source": "place_details 或 search_result",
  "fetched_at": "YYYY-MM-DD",
  "csv_type": "景點 / 起終點 / 便利商店 / 餐廳大休 / 未入選",
  "bayesian_score": 4.20,
  "visual_score": 19.40,
  "not_selected_reason": "（僅未入選地點填寫）",
  "note": "重要標記或補充說明",
  "reviews_summary": "簡短評論摘要"
}
```

### 使用規則

1. **規劃前先查快取**：執行 Phase 1 前，先讀取 `dayN/map/index.json`，確認哪些 `place_id` 已有快取資料，直接取用，**不得重複呼叫** `place_details`。
2. **search_result 可升級**：若快取來源為 `search_result`（缺少完整欄位），且該地點重新被選為候選，才補呼叫 `place_details` 並更新檔案。
3. **未入選也要存檔**：所有在候選池中出現過（有評分、曾被比較過）但最終未入選的地點，一律存入 `candidates_not_selected` 並附上 `not_selected_reason`，以利日後調整路線時快速取用。
4. **visual_score_estimate**：未入選候選的 `visual_score` 以 `_estimate` 標記（因 Bayesian C/m 以最終入選池計算，估算值僅供參考）。

## ⚠️ 注意事項

- **補給點驗證**：使用 `mcp_google-maps_maps_search_places` 工具搜尋確認便利商店/加油站是否存在且營業中
- **路線順序**：CSV 中的順序必須與實際騎乘方向一致
- **距離估算**：使用 `mcp_google-maps_maps_directions` 工具以 `bicycling` 模式計算實際騎乘距離。若 API 回傳錯誤或被停用，**備案**：改從 Phase 2 產出的 `dayN_route.gpx` 以 Python 解析 `<distance>` 欄位加總，取得實際總里程，不得以主觀估算替代。
- **撤退方案**：每日至少標註 2~3 個可中途撤退搭火車的車站
- **熱門度欄位**：「景點」「起終點」「餐廳大休」都必須填寫評分與評論總數；「便利商店」「加油站」等補給類型留空
